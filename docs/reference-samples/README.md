# 范文与模板怎么用（湖南程序设计竞赛 · 应用开发类）

> 先说结论：**湖南省赛的「系统设计说明书」不是一篇散文，而是一本合订材料。**  
> 往届获奖作品全文 PDF 基本不公开；下面给你的是目前能公开拿到的、最接近「评委口味」的范文/模板。

---

## 1. 官方到底要什么（先对齐预期）

报名系统历年说明（中南大学 HNCPC）写得很清楚，PDF 版「系统设计说明书」**可包括**：

1. 目录  
2. 功能需求说明书  
3. 概要设计说明书  
4. 详细设计说明书  
5. 数据库设计说明书（如必要）  
6. 软件界面设计书 / 界面设计说明书  
7. 用户操作手册  
8. 安装手册  

纸质要求：胶装一本、正文有目录、双面打印、白色封面封底、封面用组委会模板、一式 2 份。

所以你感觉「一篇写不完 / 写不像」，很正常——**它本来就该是多章合订**，不是单篇「作品说明书」那种宣传文。

官方报名与提交说明可参考：

- https://hnmachvi.csu.edu.cn/Hncr  
- 历年 news（如 nid=10、nid=11）里的「应用开发类作品提交」条目  

你本地的封面模板在：`docs/公告附件/` 下的「系统设计说明书封面模板.docx」。

## 2. 我帮你下好的本地范文（优先打开这些）

路径：`docs/reference-samples/`

### （A）带「示例」正文的软工文档（最推荐先看）

仓库：[cuizhenjie/software-engineering-document](https://github.com/cuizhenjie/software-engineering-document)  
本地：`docs/reference-samples/se-doc-examples/`

请直接用 Word 打开下面这些 **「示例」**（不是空模板）：

| 你要模仿的部分 | 本地文件位置（文件夹名可能显示乱码，按层级找） |
|----------------|------------------------------------------------|
| 需求怎么写 | `02 需求阶段` → `需求规格说明书 - 示例.docx` |
| 设计怎么写 | `03 设计阶段` → `功能设计说明书 - 示例.docx` |
| 数据库怎么写 | `03 设计阶段` → `数据库设计说明书 - 示例.docx` |
| 用户怎么写 | `06 验收阶段/04 使用手册` → `使用手册 - 示例.doc` |
| 安装维护 | `06 验收阶段/02 安装维护手册` → 示例 |
| 测试 | `05 测试阶段` → 测试计划/报告示例 |

**怎么学：**  
看它的章节标题、表格密度、有没有流程图/模块表；**不要抄业务内容**，只学「评委习惯读的结构」。

### （B）国标 GB 8567 章节骨架（概要/详细设计正统目录）

仓库：[eynol/software-document-boilerplate](https://github.com/eynol/software-document-boilerplate)  
本地：`docs/reference-samples/GB8567-templates/`

- `README.md`：解释「概要设计说明书又称系统设计说明书」等国标说法  
- `dot模板/`：各文档目录大纲  
- `word-templates-extracted/`（若已解压）：Word 空模板包  

概要设计（系统设计）国标常见章：引言 → 总体设计 → 接口设计 → 运行设计 → 数据结构设计 → 出错处理设计。  
详细设计：按模块写功能/输入输出/算法/流程/接口/测试要点。

## 3. 全国赛「简要开发文档」模板（对照文风，不是湖南合订本）

中国大学生计算机设计大赛（4C）强调：**简明扼要、图表为主、不宜长篇大论**。  
这和湖南「厚合订本」不完全一样，但**概要设计一页图 + 详细设计突出难点**的写法很值得学。

- 大赛资料下载：http://jsjds.blcu.edu.cn/zlxz.htm  
- 2026 模板网盘（官网公布）：https://pan.baidu.com/s/1N-fUhs2cK6e4KO1IiDXV3w?pwd=1111  
- 填写说明摘录（社区转载较全）：https://devpress.csdn.net/v1/article/detail/124420998  

建议：湖南合订本里的「概要设计」可以写短一点、多图；「详细设计」再展开算法与模块。

## 4. 为什么找不到「某年一等奖完整 PDF」

应用开发类获奖队通常只交网盘/纸质，**不会把整本系统设计说明书公开挂网**（涉及源码结构与知识产权）。  
网上能稳定找到的「极好范文」，实际是两类：

1. **结构极正**的国标/软工模板 + 填好的示例（上面 A/B）  
2. **文风极好**的 4C 简要开发文档模板（上面第 3 节）  

把这两类合起来，就接近评委想看的湖南本子。

## 5. 建议你按这个目录胶装（JoyForOld）

```text
封面（官方模板）
目录（自动生成）
第1部分  功能需求说明书
第2部分  概要设计说明书（架构、模块、接口、数据概要）
第3部分  详细设计说明书（路由/NLU/Agent/无障碍/协助等关键模块）
第4部分  数据库/数据存储说明（可简写：SharedPreferences + 协助端 H2）
第5部分  软件界面设计书（截图 + 说明）
第6部分  用户操作手册
第7部分  安装手册
附录     测试要点 / 术语表（可选）
```

创新点：放在**概要设计「设计要点」或详细设计「关键技术」**里用技术语言写；宣传性创新点留给作品说明书/PPT，不要整本说明书都在喊口号。
