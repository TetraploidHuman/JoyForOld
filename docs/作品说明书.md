# JoyForOld 作品说明书

> 参赛类别：计算机软件开发类  
> 作品名称：JoyForOld（为长辈设计的 AI 手机操控助手）  
> 版本：1.0  
> 运行平台：Android 9.0 及以上（minSdk 28 / targetSdk 36）

---

## 一、作品概述

### 1.1 作品简介

JoyForOld 是一款面向老年用户的 Android 端 **语音 + AI 图形界面操控助手**。它不止于聊天问答，而是通过系统无障碍服务「看见」当前屏幕，理解长辈用自然语言说出的意图，并代其完成点击、输入、滚动、打开应用等真实操作；在发送消息、拨打电话等关键步骤会进行 **语音二次确认**，兼顾易用与安全。同时支持家属远程协助，形成「长辈端自主使用 + 子女端远程帮一把」的照护闭环。

### 1.2 设计背景与意义

智能手机功能丰富，但 App 层级深、图标小、流程长，许多长辈面对微信发消息、高德导航、淘宝搜索、系统设置等场景仍感到困难。传统语音助手多停留在「打开 App」或「搜索」，难以完成跨界面多步操作；子女远程指导又依赖视频通话口述，效率低、易出错。

本作品将 **大模型智能体（GUI Agent）**、**端侧语音唤醒与意图理解**、**无障碍自动化** 与 **家属协同** 结合，降低数字鸿沟，服务积极老龄化与智慧助老需求。

### 1.3 目标用户

| 角色 | 需求 |
|------|------|
| 长辈（主用户） | 用说话完成日常手机操作，少记步骤、少点屏幕 |
| 家属 / 照护者 | 远程查看、发指令协助；配置亲情联系人与紧急用语 |
| 开发 / 演示 | 可配置云端 ASR/LLM，真机演示银发刚需场景 |

### 1.4 解决的核心问题

1. **操作门槛高**：把「我想干什么」变成系统可执行的 UI 动作序列。  
2. **弱网与成本**：高频指令优先走端侧模板与离线 NLU，少依赖云端。  
3. **误操作风险**：发送、拨号等敏感步骤强制语音确认。  
4. **子女帮不上忙**：协助码配对后可远程看屏、发指令，在老人手机上跑 Agent。  
5. **复杂界面可读性差**：无障碍树缺失时回退到截图多模态规划。

## 二、功能说明

### 2.1 功能总览

| 序号 | 功能模块 | 简要说明 |
|------|----------|----------|
| 1 | 语音 / 文字智能体 | 自然语言下达指令，规划并执行多步 UI 操作 |
| 2 | 无障碍操控 | 读取界面树，执行点击、输入、滚动、打开应用等 |
| 3 | 本地唤醒词 | 持续监听唤醒词，唤醒后自动进入语音输入 |
| 4 | 离线意图理解 | 端侧 ONNX 意图分类，弱网仍可完成常用任务 |
| 5 | 敏感操作确认 | 发送消息、拨号等步骤语音二次确认 |
| 6 | 银发任务模板 | 「打电话给女儿」「导航回家」「紧急呼救」等高置信短语直达 |
| 7 | 悬浮助手 | 跨应用悬浮入口，随时唤起辅助 |
| 8 | Joy 输入助手 | 专用输入法，提升自动填字稳定性 |
| 9 | 家属远程协同 | 配对、看屏、远端指令 |
| 10 | 地图导航 | 高德 POI / 深链，「导航回家」等 |
| 11 | 通知朗读 | 读未读消息等 |
| 12 | 主动关怀 | 久坐、用药记忆等轻量语音提醒 |

### 2.2 典型使用场景

1. **打电话给家人**  
   长辈说：「打电话给女儿」→ 匹配联系人 / 模板 → 拨号前语音确认 → 执行拨号。

2. **微信发消息**  
   说出要发给谁、说什么 → Agent 打开微信、选联系人、输入内容 → 发送前确认。

3. **导航回家**  
   「我要回家」→ 解析家地址 / 预设 → 调起高德导航。

4. **紧急呼救**  
   「紧急呼救」「叫家人帮忙」→ 按照护配置联系家属或发送紧急短信文案。

5. **弱网常用设置**  
   「打开 WiFi」「放大字体」「几点了」等优先走离线意图或本地系统能力。

6. **子女远程帮一把**  
   老人端显示协助码 → 家属输入协助码连接 → 查看屏幕或下发指令，在老人手机执行。

### 2.3 交互方式

- **语音**：唤醒词 → 说话；或点击麦克风 / 悬浮球。  
- **文字**：首页输入栏直接输入指令。  
- **建议芯片**：首页提供「我要回家」「帮我读一下未读消息」等一键示例。  
- **语音确认**：敏感步骤听问题，用「是 / 否」类短语确认。  
- **打断（Barge-in）**：播报过程中可再次说话打断。

### 2.4 界面结构

主界面采用 Cortana 风格分区导航：

- **助手页**：品牌光球、对话与任务步骤、建议指令、输入与语音入口  
- **设置页**：唤醒词、API、权限与偏好等  
- **协作页**：长辈 / 家属角色、协助码配对与远程指令  
- **关于页**：版本信息、历史记忆等  

视觉上以蓝色强调色与动画光球作为品牌识别，面向长辈突出大按钮式建议与口语化文案。

## 三、技术创新点

1. **面向银发群体的端云协同 GUI Agent**  
   不是单纯对话机器人，而是「观察屏幕 → 规划 → 操控真实 App」的闭环智能体。

2. **多层指令路由**  
   长辈模板 → 离线 NLU → 本地系统 Intent → 预设别名 → 云端 LLM，兼顾时延、成本与成功率。

3. **端侧 ONNX 意图分类 + 规则槽位**  
   基于中文 RoBERTa-Mini INT8，高置信自动执行、中置信澄清、低置信回退，宁可不匹配也不误执行。

4. **本地唤醒 + Silero VAD + 可选二阶段复检**  
   适配环境噪声；唤醒后预缓冲音频衔接流式 ASR，减少「唤醒后再说一遍」的负担。

5. **敏感操作语音二次确认 + 防循环守卫**  
   关键动作安全门控，降低误发、误拨风险。

6. **无障碍优先 + Vision 回退**  
   界面树可用时精准点击；树缺失（部分微信界面等）时截图多模态规划坐标点击。

7. **Action-set 脚本化高频流程**  
   微信发消息、淘宝搜索、地图选点等固化为高可靠动作集，减少纯 LLM 自由探索的不稳定。

8. **家属远程协同中继**  
   独立协助协议与服务端，支持配对房间、屏幕与指令转发。

9. **隐私脱敏**  
   上云前对页面上下文中的敏感信息（如验证码等）进行脱敏处理。

10. **主动关怀引擎**  
    面向照护场景的轻量提醒，增强「陪伴感」而非仅工具属性。

## 四、技术路线（摘要）

- **客户端**：Kotlin、Jetpack Compose、Material3、Koin、Kotlin Coroutines  
- **操控层**：Accessibility Service + 悬浮窗前台服务 + 可选 IME  
- **语音**：Sherpa-ONNX 唤醒与 Silero VAD；火山引擎豆包流式 ASR；系统 TTS  
- **理解与规划**：端侧 ONNX 意图；云端大模型工具调用（火山方舟 / DeepSeek / 智谱等可配置）  
- **协同**：Ktor WebSocket 协助服务（JWT、配对房间）  
- **地图**：高德 Web POI + `androidamap://` 深链  

详细架构、模块、接口与部署见配套《技术文档》。

## 五、运行环境与使用要求

### 5.1 硬件与系统

- Android 手机，建议 Android 9.0+  
- 麦克风可用；真机调试（模拟器无障碍与麦克风体验受限）  
- 网络：云端 ASR / LLM / 地图 / 远程协助需要联网；部分离线意图可弱网使用  

### 5.2 权限与系统服务（首次使用需开启）

| 权限 / 服务 | 用途 |
|-------------|------|
| 麦克风 | 唤醒与语音识别 |
| 无障碍服务（主服务 + 微信支持组件） | 读屏并代操作 |
| 悬浮窗 | 跨应用助手 |
| 通知权限 | 前台服务与确认提醒 |
| 通知使用权（可选） | 读未读消息 |
| 通讯录 / 日历 / 定位（按需） | 拨号、日程、导航天气等 |
| Joy 输入助手（推荐） | 稳定自动输入 |

### 5.3 云端密钥（演示环境）

需配置大模型与豆包 ASR 等密钥（`local.properties` 或 App 内 API 配置）。密钥仅存本机，勿随仓库分发。

## 七、安全与伦理说明

1. 无障碍能力仅用于协助操作，用户须知情开启。  
2. 敏感操作需语音确认，降低误触造成的财产与社交风险。  
3. API Key、偏好数据存于本机；协助链路需在可信网络部署服务端。  
4. 上云上下文支持脱敏；请勿在演示环境使用含真实隐私的账号数据。  
5. 紧急呼救依赖用户预先配置的家属信息与短信能力，不能替代专业急救体系。

## 八、应用前景

- **个人与家庭**：随家长辈手机上的「口语式操作代驾」。  
- **社区 / 养老机构**：统一配置常用指令与家属协助。  
- **适老化改造**：作为第三方能力叠加在现有 App 之上，无需各 App 单独改造。  
- **教研演示**：GUI Agent、端侧 NLU、银发 HCI 等课题的完整可运行样例。

## 九、总结

JoyForOld 以「让长辈用说话完成真实手机任务」为目标，融合端侧语音与意图、云端智能体规划、无障碍执行与家属协同，形成安全可控的银发 GUI Agent 方案。作品强调 **可用性、安全性、弱网可用性与照护协同**，适合作为软件开发类竞赛的完整工程作品展示。
