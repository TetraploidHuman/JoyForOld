## 1. 文档说明

本文档面向评审、二次开发与部署人员，说明系统架构、模块职责、AI/语音流水线、数据与权限、构建配置及扩展方式。产品定位与功能说明见《作品说明书》。

## 2. 系统目标与设计原则

| 原则 | 具体做法 |
|------|----------|
| 任务闭环 | 自然语言 → 路由/规划 → UI 执行 → 观察反馈 → 必要时再规划 |
| 端云协同 | 高频、低风险走端侧；复杂、开放域走云端 LLM |
| 安全优先 | 敏感操作语音确认；动作守卫防死循环；上云脱敏 |
| 银发优先 | 模板与建议芯片、口语确认、唤醒连说、大按钮式引导 |
| 可配置 | LLM/ASR 多供应商；协助服务地址可配 |

## 5. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     UI（Compose / 悬浮窗）                    │
│              DemoViewModel / AgentUiState                    │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                      AgentRuntime                            │
│     语音、唤醒、覆盖层、协助、权限与会话状态聚合               │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                  CommandRouteResolver                        │
│  模板 → 离线NLU → 本地系统 → 预设 → LLM AgentOrchestrator    │
└───────┬───────────────────────────────┬─────────────────────┘
        │                               │
        ▼                               ▼
  SystemIntentExecutor          AgentOrchestrator
  / Action-set DSL              （观察 → 规划 → 执行 → 再观察）
        │                               │
        └──────────────┬────────────────┘
                       ▼
            AccessibilityGateway
                       │
            JoyAccessibilityService
            （点击 / 输入 / 滚动 / 截图 / 打开应用）
```

设计模式要点：

- **门面（Facade）**：`AgentRuntime` 对外统一入口。  
- **编排循环**：`AgentOrchestrator` 实现工具调用式 Agent Loop。  
- **网关**：`AccessibilityGateway` 隔离无障碍实现。  
- **路由级联**：`CommandRouteResolver` 按优先级分流。  
- **守卫**：`AgentActionGuard` 注入确认与防重复。

## 6. 核心处理流水线

### 6.1 语音唤醒 → 识别 → 执行

```
麦克风前台服务
  → Silero VAD（语音活动门控）
  → Sherpa Zipformer KWS（自定义唤醒词）
  → 提示音 + 预缓冲 PCM（WakeChainedAudioBridge）
  → 豆包流式 ASR
  → CommandRouteResolver（见下）
  → 执行结果 → 系统 TTS 播报（支持打断）
```

说明：Sherpa 当前用于 **KWS + VAD**；完整端侧 ASR 尚未接入主路径。

### 6.2 指令路由优先级

1. `ElderTaskTemplateMatcher`：高置信银发短语模板  
2. `OfflineNluRouter`：ONNX 意图 + 规则槽位  
3. `SystemIntentLocalParser` / AI 辅助系统意图解析  
4. `LocalCommandParser`  
5. `PresetCommandStore` / 预设意图  
6. 否则进入 `AgentOrchestrator` 云端 LLM 工具循环  

### 6.3 Agent 工具循环（云端路径）

1. **观察**：无障碍 UI 树；树为空或不足时截图进入 Vision 模式。  
2. **规划**：LLM 按工具 Schema 返回 JSON 动作（点击文本、坐标点击、输入、滚动、打开 App、结束等）。  
3. **守卫**：敏感动作注入语音确认；检测重复无效动作。  
4. **执行**：经 `JoyAccessibilityService` 操作目标 App。  
5. **再观察**：根据新状态继续或结束，并用 TTS 反馈用户。

### 6.4 离线 NLU

| 项 | 内容 |
|----|------|
| 基座 | `uer/chinese_roberta_L-4_H-256`（约 4 层 / 256 维） |
| 部署 | INT8 ONNX，约十数 MB 量级 |
| 资产 | `app/src/main/assets/nlu/`（`intent_classifier.onnx`、`vocab.txt`、标签与阈值配置等） |
| 训练 | `tools/nlu/train_and_export.py` |
| 门控 | 高置信自动执行、中置信澄清、低置信拒绝并回退（阈值见 `encoder_config.json`） |
| 评测 | `tools/nlu/holdout/` 独立 hold-out 集 |

典型意图类别包括：Wi‑Fi/蓝牙/设置、打开应用、闹钟日历、相机、天气、拨号联系人、导航回家、紧急求助、叫家人帮忙、健康码/付款码、以及 `none` 等。

### 6.5 唤醒模型

| 项 | 内容 |
|----|------|
| 结构 | Zipformer 小型 transducer（拼音单元） |
| 来源 | WenetSpeech 训练量级数据，sherpa-onnx 推理 |
| 资产 | `app/src/main/assets/wakeword-sherpa/` |
| 增强 | Silero VAD、可配置阈值、说话人标定、可选二阶段复检 |

## 7. 关键子系统说明

### 7.1 无障碍操控

- 主服务：`JoyAccessibilityService` — 读取节点树、按文本打分点击、手势滚动、截图等。  
- 微信支持组件：额外无障碍读屏服务，用于部分白名单界面树访问（需与主服务同时开启）。  
- 输入：优先通过 Joy IME 写入；失败可回退剪贴板粘贴策略。

### 7.2 敏感操作与安全

- 发送消息、拨号等触发确认话术。  
- `VoiceConfirmPhraseMatcher` + 短时 ASR 解析肯定/否定。  
- `AgentActionGuard`：确认注入、防循环。  
- `PageContextRedactor`：上云前脱敏（如 OTP 等）。

### 7.3 家属远程协助

- 协议：`assist-protocol` 定义控制与会话消息。  
- 服务：`assist-server` 提供配对房间、JWT、WebSocket 屏幕/指令中继。  
- 客户端：`AssistSessionManager`；UI 在协作页区分「我是老人」与家属侧输入协助码。  
- 默认调试地址示例：`http://10.0.2.2:8787` / `ws://10.0.2.2:8787/ws`（模拟器访问宿主机）。

### 7.4 悬浮窗与前台服务

- `FloatingOverlayService`：跨 App 助手入口。  
- `WakeWordService`：麦克风类前台服务持续监听唤醒。  
- 通知渠道：服务存活提示、语音确认提醒等。

### 7.5 主动关怀

- `ProactiveAssistantEngine`：基于不活跃时长、用药记忆等触发轻量口语提醒，带冷却，避免打扰。

## 8. 数据存储

应用内 **未使用 Room**；以 SharedPreferences 为主：

| 存储类 / 键域 | 用途 |
|---------------|------|
| API Key 相关 | LLM / ASR 密钥 |
| WakeWordConfigStore | 唤醒词、阈值、VAD/二阶段开关 |
| AgentMemoryStore | 对话记忆 |
| AgentSessionStore | 待确认会话 / 恢复 |
| CaregiverSupportStore | 家属联系人、紧急短信文案 |
| PresetCommandStore | 照护者定义的指令别名 |
| AssistPairingStore | 协助绑定状态 |
| ThemePreferenceStore | 明暗主题 |
| AsrSpeakerProfileStore | 标定 → ASR 纠错映射等 |

协助服务端使用 H2 持久化配对与会话元数据。

模型与词表等静态资源位于 `assets/`（唤醒、NLU）。

## 10. 构建与配置

### 10.1 环境

- Android Studio 或 JDK 11+  
- Android SDK（与 compileSdk 36 匹配）  
- 真机 + 开启无障碍与悬浮窗  

### 10.2 密钥配置

复制 `local.properties.example` 为 `local.properties`（勿提交），按需填写：

- LLM：`llm.api.key` / `llm.model` / `llm.base_url`（或兼容的 DeepSeek、智谱、火山项）  
- ASR：`volc.asr.api_key` 或旧版 `app_id` + `access_token`  
- 协助：`assist.server.url` / `assist.server.ws`  
- 地图：高德 Web Key（若启用导航 POI）  

亦可在 App 内 API 配置区写入，存于本机 prefs。

### 10.3 常用命令

```bash
./gradlew :app:assembleDebug
./gradlew :assist-server:run   # 按模块实际运行方式为准
```

离线 NLU：

```bash
pip install -r tools/nlu/requirements.txt
python tools/nlu/train_and_export.py
python tools/nlu/eval_holdout.py
```

## 12. 测试与调试建议

1. **权限清单检查**：无障碍双服务、悬浮窗、麦克风、通知。  
2. **路由分层验证**：先测模板与离线 NLU（可断网或关 LLM Key），再测开放域 Agent。  
3. **敏感确认**：故意触发发消息/拨号，验证确认话术与肯定/否定分支。  
4. **微信路径**：确认微信支持组件已开；必要时开 Vision 调试。  
5. **协助链路**：本机起 `assist-server`，老人端与家属端同网配对。  
6. **NLU 回归**：`eval_holdout.py` 做泄漏检查与准确率；真机 ASR 录音集见 `tools/nlu/holdout/`。  
7. **UI 树**：可使用 `uitreetest` 或 logcat UI 树输出辅助定位点击失败原因。

## 13. 已知边界与后续方向

| 边界 | 说明 |
|------|------|
| 端侧 ASR | 尚未作为主识别路径，依赖云端豆包 ASR |
| App 适配 | 依赖无障碍树质量；强加密/游戏类界面能力有限 |
| 紧急呼救 | 依赖预配置与运营商短信能力，非专业急救替代 |
| 服务端部署 | 生产环境需 HTTPS/WSS、鉴权加固与运维方案 |

可选后续：完整端侧 ASR、更多 App Action-set、家庭多设备管理、无障碍节点缓存与强化学习式策略等。
